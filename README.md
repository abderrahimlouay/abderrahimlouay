## 🧭 How I like to build

- **Plan first, then code.** IMS Vétérinaire has a requirements doc, an architecture doc, a data model, a glossary, a phased roadmap and numbered decision records (ADRs) before and alongside the code.
- **Rules live in the backend.** Stock can't go negative, expired or recalled lots can't be sold, money records are reversed rather than edited. Each rule has an ID and a test.
- **Real databases in tests.** Integration tests run on Testcontainers MySQL, architecture rules are enforced with ArchUnit, and CI runs lint, typecheck, unit, end-to-end and a secret scan on every push.
- **Hardware and maths for fun.** I keep coming back to things I can see move: simulations, gesture tracking and blinking LEDs.
